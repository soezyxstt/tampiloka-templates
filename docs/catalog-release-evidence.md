# Catalog release evidence

Catalog publication compares the proposed feed with the currently hosted feed before deploying. New public entries, changed demo or image URLs, and changed source fingerprints require hosted evidence. Missing or failed evidence retains that family's verified release, routes and images while name, description, mode-label and featured-flag edits can still publish for that same family. Independent families can publish separately. Explicit removals stay removed. A missing or invalid existing feed stops publication.

`release-demos.yml` owns deployments for Cafe Pages and the Commerce, School and Booking Workers. Each family job tests and builds the exact checkout, stamps its assets with the source fingerprint, commit and asset digest, deploys those files, exercises hosted customer/staff flows and verifies hosted preview bytes. Only then does it upload an immutable Actions artifact identifying the successful release. Release and catalog jobs share a queue. `school.yml` retains local quality gates; the old manual Workers workflow forwards to the release workflow.

The catalog computes each family's 40-character source fingerprint from Git objects for its template and shared runtime/build inputs. This detects a changed build even if all public URLs stay the same. It injects that identity into the candidate feed; contributors do not manually pin releases. A completed release run automatically triggers publication. The gate requires a successful family job, an artifact from that exact main-branch run with the matching fingerprint and commit, and matching hosted identity at every candidate origin. Failed jobs from other families do not prevent an independently verified family from publishing. No marketing edit is required.

New families require a deployment job and evidence registration before promotion. Image HEAD checks alone cannot certify a release. Run `pnpm test:registry` for negative and positive promotion tests. Actions needs read access to runs and artifacts; deployments use the existing Cloudflare account/API-token secrets. Evidence artifacts are retained for 90 days; a new promotion after expiration requires a fresh verified release. Previously verified unchanged families remain public.

Deployment access controls remain necessary: out-of-band deploys can overwrite a previously verified origin after publication. Disable legacy Cafe Pages Git deployments from the old repository when adopting this workflow; the canonical uploader is this repository's release job. An unstamped or overwritten origin fails subsequent promotion. Initial recovery from a missing catalog requires an operator-controlled bootstrap. Local tests verify the gate's behavior; hosted Actions and provider permissions must pass on the actual release before claiming live acceptance.
