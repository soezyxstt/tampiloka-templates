# Catalog release evidence

Catalog publication compares the proposed feed with the currently hosted feed before deploying. New public entries, changed demo or image URLs, and changes to a family's `release` require hosted evidence; copy and featured-flag edits do not. The current feed must be reachable and valid, and any missing or failed evidence stops the deployment, leaving the existing Worker untouched. The generated feed records an optional 40-character `release` commit on each family so the next publication can compare it.

School is the supported release source: the latest main-branch push run of `school.yml` must match the pinned commit, finish successfully, and contain a successful `deploy-demo` job. That job deploys the tested build and exercises hosted API, browser journeys and preview bytes. The deployment and catalog jobs share a queue to avoid overlapping promotion with a School deployment. Only main push runs deploy School; feature and manual runs are verification only. A completed School run retriggers the catalog workflow against current main, so an already-proposed promotion can publish after the gate succeeds. The GitHub Actions token needs read access to Actions runs and jobs.

To promote School, first merge and successfully deploy the demo revision. Then set `release` on the School family in `packages/registry/public-demos.json` to the exact 40-character commit SHA from that deployment and merge the catalog metadata. If the demo changes again, pin the new verified deployment commit. Publishing a release does not require a marketing-site change. Do not remove or reuse the pin to represent a different build. Existing entries without a pin are grandfathered for copy edits; any subsequent promotion requires one.

Cafe, commerce, booking and new families currently lack an equivalent deployment-and-hosted-smoke job wired to this gate. Their existing entries can receive copy edits, but new or changed demo routes/images and release promotions fail closed until a trusted family-specific workflow is implemented and registered in `scripts/check-catalog-promotion.mjs`. A successful image HEAD request is not release evidence. The gate cannot prove a Worker was not modified outside these repository workflows; retain deployment access controls. Initial publication requires an existing verified catalog; recovery from its absence requires an operator-controlled bootstrap.
