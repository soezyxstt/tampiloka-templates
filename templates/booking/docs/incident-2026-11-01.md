The deployed Worker returned 500 for fresh `/api/bootstrap` and demo configuration requests while `/api/health` returned 200. The request logs omitted the underlying error, but scheduled cleanup logs on November 1 report that the account exceeded D1's free-tier daily row-write limit; a bootstrap failure occurred during that same period. The account limit resets at midnight UTC. A fresh bootstrap returned 200 on November 2 without deploying this PR. A health response does not exercise session writes or seeding.

Cloudflare D1 analytics show the Booking database wrote approximately 109,166 rows on November 1. Query insights identify demo resource-unit and entity initialization and cascading scope cleanup as major write sources. Each fresh session used to initialize all four presets; this change initializes the default preset and creates each other preset only when first selected. Existing preset edits remain intact. This reduces writes but does not guarantee the shared account stays below its quota: monitor account-wide usage and provide sufficient D1 capacity for actual traffic and hosted verification.
